# Knowledge catalog

`spec/knowledge/` is the canonical, machine-readable join across Zaibatsu's
rules evidence, structured data, assets, docs, and workflow state.

This layer is intentionally separate from runtime content:

- `spec/data/` stays engine-facing and gameplay-oriented;
- `spec/provenance/` stays the source-verification record;
- `spec/assets/manifest.json` stays the physical-asset manifest;
- `DOCS/rules/transcripts/` stays the tracked source-text layer;
- `spec/knowledge/` answers cross-cutting questions such as:
  - what this thing is;
  - where it is documented;
  - which source artifact or asset backs it;
  - what it is related to;
  - whether it is provisional, cataloged, verified, or implemented.

## Files

- `taxonomy.json` - allowed tags and relation types.
- `catalog.json` - one entry per tracked entity.
- `relations.json` - explicit edges between entries.

## Ownership

`taxonomy.json` is hand-maintained. `catalog.json` and `relations.json` are
generated by `bun tools/build-knowledge.ts` from the existing canonical files.
Do not hand-edit generated outputs.

`DOCS/knowledge/` remains the human-facing guide to this catalog.

## Rule and component coverage

`implementation.json` is the authored source/runtime/test evidence overlay. `coverage.json` is generated by `bun tools/rules-coverage.ts` from that overlay, every reviewed asset, registered rule modules and the eight-mode inventory. Verify freshness with `--check`. This output is a checklist of physical source records and rule groups, not a count of unique gameplay entities or a percentage of completed game rules. Source-verified and runtime-implemented are independent properties.
